# Devpost: "PayPal in HaggleBot" paragraph (every claim below is true of the code today)

PayPal is the source of truth in HaggleBot, not just the last step. A buyer haggles with an AI, plain code keeps the price above the seller's floor, and the payment runs through PayPal Orders v2 (capture, or authorize then capture for services), with refunds, voids, idempotent requests and signature-verified webhooks. The seller dashboard then asks PayPal, by capture ID, whether the money really arrived: "PayPal confirms $41.50 received", with mismatches flagged. Every deal keeps a money trail of real PayPal order, capture and refund IDs, `debug_id`s and verified webhook events. A seller Copilot works through PayPal tools (the tool names follow PayPal's agent tools), but it can only propose a refund or capture: PayPal executes it only after the seller clicks Confirm, and a test proves a prompt-injected chat transcript cannot trigger a refund. We also connect to PayPal's remote MCP server (46 tools discovered); its tool execution was blocked on PayPal's side during testing, so the app uses the REST API and labels which transport served each call.

Not claimed: Venmo, invoicing, and account-level Transaction Search (they need sandbox features that are not enabled for our app).
